Whitepaper — The Economics of Building Software

The New SDLC With Vibe Coding

Generation is solved. As 41% of new code goes AI-generated, the whitepaper argues the developer's real job is shifting from writing software to designing the system — and the judgment — that produces it.

Addy Osmani · Shubham Saboo · Sokratis KartakisGoogle · May 2026· 49 pp
Read the full whitepaper (PDF) →

For most of computing history, programming has been an act of translation: understand the problem in human terms, design a solution in abstract terms, then render it in syntax a machine can execute. Every step adds friction — and that friction is now collapsing. The whitepaper's claim is blunt: this is the biggest shift since high-level languages. As of early 2026, 85% of professional developers use AI coding agents, 51% daily, and an estimated 41% of all new code is AI-generated.

01A spectrum, not a slur

"Vibe coding" — Karpathy's February 2025 coinage for fully giving in to the vibes and forgetting the code exists — became so broad it lost meaning. The authors reframe it as one end of a spectrum that runs to disciplined "agentic engineering." The real differentiator isn't whether you use AI; it's how much structure, verification, and human judgment surround the output. Telling a CTO your team vibe-codes the payment system should raise alarms; telling them you practise agentic engineering — AI implementing under human-designed constraints, with tests proving correctness — is a different conversation.

"The single biggest differentiator between the two ends is how outputs get verified. Without tests and evals, the practice is always vibe coding."

02Context engineering is the real skill

Quality depends less on clever prompts and more on the quality of context. The paper names six types — instructions, knowledge, memory, examples, tools, guardrails — and a central trade-off between static context (always loaded; rule files like AGENTS.md, CLAUDE.md, GEMINI.md — reliable but expensive) and dynamic context (loaded on demand; efficient). The most powerful pattern is Agent Skills: portable packages of procedural knowledge loaded only when a task calls for them, so an agent stays a lightweight generalist that flexes into a specialist on demand.

03The factory model

The mental model that ties it together: the developer's primary output is no longer code — it's the system that produces code. A factory manager doesn't assemble every widget; they design the assembly line and own quality control. Which leads to the paper's central equation:

Agent = Model + Harness

The model is roughly 10% of what you experience; the other 90% is the harness — prompts, tools, sandboxes, orchestration, hooks, observability. The proof is concrete: on Terminal Bench 2.0 one team moved a coding agent from outside the Top 30 into the Top 5 by changing only the harness, no model change at all. The everyday lesson: when an agent fails, the instinct is to blame the model — but "most agent failures, examined honestly, are configuration failures."

04Conductor & orchestrator

The developer moves between two modes. As a conductor they work real-time in the IDE, directing an AI pair-programmer keystroke by keystroke (Copilot, Gemini Code Assist, Cursor, Windsurf). As an orchestrator they operate at a higher level — defining goals, delegating to async, multi-agent background workers and reviewing results (Jules, Cursor background agents, Claude Code). The orchestrator skill set is specification, decomposition, evaluation, and system design — not syntax fluency.

05The 80% problem

Agents rapidly produce ~80% of a feature; the last 20% — edge cases, error handling, integration, subtle correctness — needs deep context models often lack. Headline gains are real (industry surveys cite 25–39%) but nuanced: a METR study found experienced developers took 19% longer on some tasks, the time spent verifying and correcting AI output. The effective posture: use AI for what it's good at, and reserve your attention for what it struggles with.

06The economics: CapEx vs OpEx

For leaders, the real metric isn't velocity but total cost of ownership. Vibe coding looks cheap — low CapEx — but carries a heavy, compounding OpEx: token burn from unverified prompting loops, a maintenance tax on inconsistent "spaghetti" code, and security remediation. Agentic engineering flips it: higher upfront CapEx (specs, test suites, context design) buys a dramatically lower marginal cost per feature. Context engineering becomes a financial lever, and intelligent model routing — big models for hard tasks, cheap ones for the routine — drives token cost down without sacrificing quality.

The same terminal workflow that makes a prototype now makes a production agent. Google's Agents CLI bundles seven skills covering the full ADK lifecycle — scaffold, code, evaluate, deploy, observe — and works with whichever coding agent you already use, so the prototype on your laptop yesterday can serve real users today without a rewrite. (That's the hands-on companion in this issue.)

07Intent as the new interface

Three durable principles close the paper: structure scales, vibes don't; AI amplifies your engineering culture (it multiplies strengths and weaknesses alike); and the human role is evolving, not diminishing — the skills that matter are shifting from implementation to judgment. Or, as the final line puts it:

"Generation is solved. Verification, judgment, and direction are the new craft."
