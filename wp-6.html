Google Software Engineers saw their daily routine flip 180 degrees in 2025. Tools like Antigravity and Gemini CLI don't just suggest text — they use tools, execute tasks, and churn out a thousand lines of well-documented code rapidly. It feels, Boonstra writes, like hiring "a legion of interns who never sleep and never complain." But there is a catch.

01The Illusion of Speed

When AI writes code much faster, it can also generate mistakes at an unprecedented rate. Velocity has hit overdrive — but the bug-to-code ratio remains a challenge. The whitepaper calls this the Illusion of Speed: you feel productive, but you're producing reviewable drafts, not production software. The bottleneck has shifted. Implementation is no longer the hard part. Verification is.

"Vibe Coding is not Vibe In Production."

The escape route is counterintuitive: since AI can write more comprehensive test coverage than any human could in the same timeframe, let it. Treat that test coverage as the programmatic, objective definition of "correct" — the mechanism that converts velocity into confidence.

02Code is disposable. Specs are forever.

Spec-Driven Development (SDD) flips the traditional hierarchy. Instead of code being the source of truth and documentation being the afterthought, the specification becomes the highest-leverage artifact a human produces. Code is generated from it — and can be regenerated at any time. If a spec is precisely written, the AI has narrow room to hallucinate or drift.

The SDD artifact stack is a constitution of files: a constitution.md defining immutable project-wide principles (the laws every agent must follow), a spec.md defining feature contracts and behavior, a plan.md as the architecture blueprint reviewed before any code generation begins, and tasks.md as granular, dependency-ordered work items. Humans edit the spec; agents execute from it.

The skill that matters has shifted from typing the implementation to defining the intent precisely enough that a machine can't get it wrong.

03Gherkin: writing specs machines can execute

The whitepaper's practical tool for spec precision is Gherkin — the Given/When/Then syntax from Behavior-Driven Development. A Gherkin scenario describes the exact state a system must reach, not the steps or API calls to get there. This gives the agent room to choose the implementation while eliminating ambiguity about what "done" means.

Crucially, Gherkin scenarios compile directly into failing tests. The agent's goal ceases to be "understand what the user wants" — open-ended and drift-prone — and becomes "make these specific scenarios green." Ambiguity collapses at the specification stage rather than leaking into production code. Security constraints (role access, data boundaries) encoded as spec scenarios get enforced by the test suite, not by someone remembering to add a guard clause.

04Zero-trust development pipelines

In the era of agents that never sleep, human-in-the-loop code review becomes a bottleneck. The whitepaper's answer is a hybrid Policy Server — an automated code-review agent that enforces the spec before any human reviews a diff. It checks for OWASP failures, verifies that the implementation respects the spec's security constraints, and blocks promotion if tests fail.

This is zero-trust applied to your development pipeline: no commit is assumed safe just because an AI wrote it. The harness itself is the trust boundary. The result is that velocity and safety stop being in tension — the policy server lets the coding agent move fast while maintaining enforceable guardrails. Combined with the MCP and A2A protocols from earlier in the series, "isolated custom machines" become a modular, interoperable fleet governed by agreed-upon open standards.

05Eval-gated deployment

Traditional CI/CD checks whether functions behave as expected. For agents, that's necessary but insufficient. An agent can pass 100% of unit tests and still fail in practice by choosing the wrong tool, hallucinating intermediate steps, or violating a guardrail it was never tested against. Boonstra's answer is evaluation-gated deployment in three stages:

Sandbox — internal testing against the eval suite. Fast checks: linting, unit tests, a lightweight agent eval. Catch obvious issues before they touch main. Canary — the agent deploys to a staging environment and runs heavier integration tests against real services, load tests, and internal dogfooding. Production — the exact same artifacts are promoted, usually with a human approval step. "Works on staging, breaks in prod" drift is eliminated because you're promoting artifacts, not re-running builds.

06The complete picture

This capstone paper closes the loop on the entire series. Day 1 established that intent is the new interface and specs are the new craft. Day 2 showed how to scaffold and deploy agents with ADK. Day 3 added the open protocols (MCP/A2A) that make agents interoperable. Day 4 added the security and evaluation frameworks to trust them. Day 5 ties it together: specs as the durable source of truth, code as disposable output, pipelines as zero-trust enforcement.

The production Google engineer in 2026 writes the spec with precision — constitutions, Gherkin scenarios, plan files — and lets the agent generate, test, and propose. The engineer's role is not implementation. It is intent, governance, and quality control.

"The developer's output isn't code — it's the factory that produces code."
— WP1, now complete.

The Takeaways

  • Illusion of SpeedAI writes code fast and bugs fast. Velocity without structure is brittle.
  • Code is disposableSpecs are the durable artifact. Generate code from them; regenerate anytime.
  • Gherkin specsGiven/When/Then scenarios compile to failing tests — binary, unambiguous, AI-executable.
  • Policy ServerAutomated code-review agent enforces the spec before human review — zero-trust by default.
  • Eval-gated deploySandbox → canary → production. Promote artifacts, not re-builds. Human approval gate.
  • The full seriesSpec (Day 1) + ADK (Day 2) + MCP/A2A (Day 3) + Security/Evals (Day 4) + SDD (Day 5) = production-grade agent fleet.
