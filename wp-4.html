Whitepaper — Procedural Memory for AI Agents

Agent Skills

Every time you dump every instruction into a single system prompt, you pay twice: once in tokens, once in quality. Agent Skills fix that with a folder and a markdown file — and in doing so, they solve the one type of memory LLMs have always lacked.

Debanshu Das · Gabriela Hernandez Larios · Lavi Nigam · Smitha Kolan · Tanvi SinghalGoogle · June 2026
Read the whitepaper on Kaggle →

There is a well-understood failure mode in AI agent development that every practitioner hits. You want a capable agent, so you write extensive instructions. The more you add, the more complete the prompt feels — and the worse the agent performs. This is context rot, and it's not a prompt engineering problem. It's a structural one. This whitepaper names the structural fix: Agent Skills.

01Four friction points, one solution

The paper frames Agent Skills as the answer to four distinct problems that have plagued AI agent development simultaneously:

Context rot. LLM performance degrades as system prompts grow. The model attends to everything, foreground and background alike — which means burying critical instructions under general ones is actively harmful. Skills solve this by loading exclusively on demand: the agent doesn't carry the weight of a skill until the task calls for it.

The procedural memory gap. LLMs have reasonable analogs for two kinds of memory: episodic (what happened in this conversation) and semantic (facts from training). What they've lacked is procedural memory — a reliable way to know how to do something step by step. The paper argues that Agent Skills are "the first credible procedural memory primitive for LLM Agents." That's a significant claim. Skills package workflows, not facts — the agent learns how to deploy, not just that deploying is possible.

"Agent Skills can be seen as the first credible procedural memory primitive for LLM Agents."

Multi-agent overload. The ecosystem was flooded with complex multi-agent systems that are notoriously hard to build and maintain. Skills offer a lighter-weight alternative: a single general-purpose agent that flexes into many specialist roles on demand. Not every task needs an orchestra. Sometimes you just need one very well-prepared musician.

Portability. A folder with a markdown file is a remarkably lightweight primitive. Any agent with filesystem access can use it — Claude Code, Codex, Gemini CLI, or anything else with an AGENTS.md–style convention. In a multi-vendor AI landscape, that portability is not a nice-to-have. It's survival.

02Anatomy of a skill

A skill is a directory containing a SKILL.md file, plus optional subdirectories: scripts/ for runnable automation, references/ for deep technical content, and assets/ for supporting files. The SKILL.md is the entry point — it contains the skill's name, a description of when to activate it, and the step-by-step instructions the agent follows when it does.

03Progressive disclosure: the key mechanism

The mechanism that makes skills work at scale is progressive disclosure, a two-phase loading strategy. At startup, the agent loads only compact metadata summaries: name, a one-line description, and trigger conditions. These occupy minimal context. When a task matches a trigger, the full SKILL.md loads. Deep reference material — technical specifications, large codebases, detailed runbooks — loads only when the skill explicitly requests it.

The practical result: an agent can carry dozens of specialised capabilities while paying the token cost for only the one it's actively using. "Generallist at idle, specialist on demand" is the operating model. This also means skill libraries can scale to enterprise breadth without degrading performance on any individual task — because the context window only ever sees one skill's depth at a time.

04Builder vs Developer: two personas

The paper explicitly serves two audiences. Builders are those using skills: they install published skills, configure them for their context, and trust that the agent will load them at the right moment. The cognitive overhead is low — point the agent at a skills directory and the machinery handles the rest.

Developers create, version, and manage skills. For them, the paper covers evaluation strategies (how do you know a skill is actually working?), production readiness (what makes a skill safe to deploy in an enterprise context?), meta-skills (skills that manage other skills), and composition (combining skills to cover complex, multi-stage workflows).

"A folder with a markdown file is a remarkably lightweight primitive. Any agent with filesystem access can use it — perfectly portable across a multi-vendor AI landscape."

05Why this matters now

The adoption velocity the paper notes is not accidental. Skills arrived at the exact moment the ecosystem needed them: agent frameworks proliferating, context windows growing but not unlimited, enterprise customers demanding repeatable workflows rather than one-off demonstrations. The whitepaper situates Agent Skills as the connective tissue between the promise of agentic AI and the reality of production deployment.

Alongside Paper 1's "context engineering is the real skill" and Paper 3's protocols for tool connection, Agent Skills complete the trio: now you know what an agent is, how it connects to the world, and how to give it portable, reproducible knowledge about how to act in it.
